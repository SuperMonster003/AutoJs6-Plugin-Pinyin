### Введение

******

Плагин Pinyin (Pinyin Plugin) добавляет в AutoJs6 автономное преобразование китайского текста в пиньинь. После установки скрипты через глобальный объект `pinyin` преобразуют китайский текст в пиньинь в нескольких стилях, с поддержкой кандидатов для иероглифов с несколькими чтениями, словаря словосочетаний, сегментации Jieba и режима фамилий, что полезно для сортировки, поиска, индексации по первым буквам, фонетической разметки и других сценариев автоматизации.

Плагин поставляется как отдельно устанавливаемый APK, работающий в собственном процессе; AutoJs6 обнаруживает его автоматически через механизм плагинов и общается с ним по AIDL. Словари одиночных иероглифов, словосочетаний и сегментации полностью встроены (APK занимает около 6 MB), поэтому преобразование выполняется целиком на устройстве без доступа к сети. Начиная с AutoJs6 v6.8.0 модуль `pinyin` хоста реализуется этим плагином. Дизайн API следует широко используемой в экосистеме JavaScript библиотеке [pinyin](https://github.com/hotoo/pinyin), так что знакомые с ней пользователи могут начать сразу.

Этот плагин и [Pinyin4j](https://github.com/SuperMonster003/AutoJs6-Plugin-Pinyin4j) являются родственными плагинами: у этого плагина полные словари с поддержкой нескольких чтений и сегментации для сценариев, где важна точность чтений; Pinyin4j основан на классической Java библиотеке pinyin4j, занимает лишь около 0.3 MB и подходит для легкого поиероглифного преобразования. Оба можно установить одновременно; подробнее в разделе `Сравнение Родственных Плагинов` ниже.

### Основные Возможности

******

- Работает из коробки: после установки AutoJs6 обнаруживает плагин автоматически, перезапуск хоста не нужен, скрипты сразу используют глобальный объект `pinyin`.
- Полные словари: встроены три словаря (одиночные иероглифы, словосочетания, сегментация) и модель HMM; все полностью офлайн, без единого сетевого запроса.
- Поддержка нескольких чтений: параметр `heteronym` возвращает все варианты чтения каждого иероглифа, а словарь словосочетаний автоматически выбирает употребительные чтения.
- Сегментация Jieba: параметр `segment` включает разбиение на слова и устраняет неоднозначность чтений по словосочетаниям, повышая точность разметки целых предложений.
- Шесть стилей пиньиня: знаки тона, цифровые тоны, цифра сразу после финали, без тонов, только инициали, только первые буквы; покрывают сортировку/поиск/разметку и другие сценарии.
- Режимы имен собственных: `SURNAME` предпочитает фамильные чтения, а `PLACE_NAME` сначала применяет отобранный корпус топонимов с прослеживаемыми источниками, затем возвращается к обычному преобразованию.
- Комбинируемые результаты: двумерный массив кандидатов, возвращаемый `convert`, несет метод `compact()`, который за один шаг разворачивает все комбинации чтений.
- Многоязычность: метаданные плагина, инструкции, README и журнал изменений доступны на 10 языках.

### Использование

******

1. Обновите AutoJs6 до внутренней сборки 3923 (6.7.1 Alpha4) или выше; с v6.8.0 преобразование в пиньинь полностью возложено на плагины, поэтому рекомендуется последняя версия.
2. Скачайте APK плагина со страницы [Releases](https://github.com/SuperMonster003/AutoJs6-Plugin-Pinyin/releases) и установите его на устройство с AutoJs6, либо установите онлайн прямо из центра плагинов AutoJs6.
3. Откройте центр плагинов AutoJs6 и убедитесь, что плагин `Pinyin` распознан, авторизован и включен.
4. Вызывайте глобальный объект `pinyin` в скриптах, как показано в разделе `Быстрый Старт` ниже; можно сначала выполнить скрипт из раздела `Самопроверка`, чтобы убедиться, что плагин работает.

> Плагин поставляется единственным универсальным APK (чистая JVM реализация без вариантов под архитектуры CPU) и поддерживает устройства с Android 7.0 (API 24) и выше. У плагина нет собственного интерфейса, он не создает значок на рабочем столе; AutoJs6 обнаруживает его и управляет им централизованно.

### Быстрый Старт

******

Базовое преобразование: `convert` возвращает двумерный массив кандидатов, `simple` возвращает компактную строку:

```javascript
console.log(pinyin.convert("中心"));                     // [["zhōng"], ["xīn"]]
console.log(pinyin.convert("中心", { style: "TONE2" })); // [["zhong1"], ["xin1"]]
console.log(pinyin.simple("拼音插件"));                  // "pinyinchajian"
console.log(pinyin.simple("拼音插件", true));            // "pin1yin1cha1jian4"
```

Несколько чтений: параметр `heteronym` возвращает все варианты, а `compact()` разворачивает их комбинации:

```javascript
let result = pinyin.convert("重庆", { heteronym: true });
console.log(result);
console.log(result.compact());
```

Сегментация для устранения неоднозначности, режим фамилий и режим топонимов:

```javascript
console.log(pinyin.simple("音乐重要", false, true));
console.log(pinyin.convert("单田芳", { mode: "SURNAME" }));
console.log(pinyin.convert("六安", { mode: "PLACE_NAME" })); // [["lù"], ["ān"]]
console.log(pinyin.convert("六安", {
  customDictionary: { "六安": [["liú"], ["ān"]] },
})); // [["liú"], ["ān"]]
```

### Стили Пиньиня

******

Параметр `style` управляет стилем вывода пиньиня; пример для "中" (zhōng):

| Стиль | Вывод | Описание |
|---|---|---|
| `TONE` | `zhōng` | Знаки тона над финалью (по умолчанию) |
| `TONE2` | `zhong1` | Цифра тона 0-4 добавляется в конец слога |
| `TO3NE` | `zho1ng` | Цифра тона сразу после финали |
| `NORMAL` | `zhong` | Без тонов |
| `INITIALS` | `zh` | Только инициаль (пустая строка для слогов без инициали) |
| `FIRST_LETTER` | `z` | Только первая буква слога |

Значение `style` не зависит от регистра; можно передать строку (например `"TONE2"`) или константу (например `pinyin.STYLE_TONE2`).

### Параметры

******

`pinyin.convert(text, options)` поддерживает следующие параметры:

| Параметр | По умолчанию | Описание |
|---|---|---|
| `style` | `TONE` | Стиль пиньиня, см. `Стили Пиньиня` выше |
| `mode` | `NORMAL` | Режим преобразования: `NORMAL` для обычного текста, `SURNAME` для фамилий, `PLACE_NAME` для отобранных чтений топонимов |
| `segment` | `false` | Включает сегментацию Jieba и словарь словосочетаний для устранения неоднозначности чтений |
| `heteronym` | `false` | Возвращать все варианты чтения каждого иероглифа, а не только первый |
| `group` | `false` | Объединять кандидатов пиньиня по выделенным словам (вместе с `segment`) |
| `customDictionary` | `{}` | Переопределения чтений иероглифов только для текущего вызова в формате `{ фраза: [[кандидаты с тонами], ...] }`; выбирается самое длинное совпадение, данные не сохраняются и требуют совместимых AutoJs6 и плагина |

Режимы также принимают константы (например `pinyin.MODE_PLACE_NAME`). `PLACE_NAME` использует самое длинное совпадение в небольшом корпусе с ручной проверкой; для отсутствующего текста применяется `NORMAL`. Это не полный государственный каталог; см. [корпус и источники](https://github.com/SuperMonster003/AutoJs6-Plugin-Pinyin/blob/master/docs/dictionaries/place-names.md).

### API Скриптов

******

Глобальный объект `pinyin` предоставляет следующие методы (прямой вызов `pinyin(text, options)` эквивалентен `pinyin.convert`):

```text
pinyin(text, options?)                   -> string[][]
pinyin.convert(text, options?)           -> string[][]
pinyin.simple(text, numeric?, segment?)  -> string
pinyin.compare(textA, textB)             -> number
pinyin.compact(matrix)                   -> string[][]
pinyin.fromCodePoint(codePoint)          -> string | null
pinyin.fromPhrase(phrase)                -> string[][]
pinyin.STYLE_* / pinyin.MODE_*           -> constants
```

- `convert` возвращает двумерный массив: каждый иероглиф или позиция словосочетания занимает одну строку с вариантами чтения; неизвестные и некитайские символы занимают строку как есть. Возвращаемый массив несет метод `compact()`, разворачивающий все комбинации чтений.
- `simple` возвращает компактную строку: первые чтения иероглифов просто склеиваются; `true` вторым аргументом дает цифровые тоны (стиль TONE2, иначе без тонов), `true` третьим аргументом включает сегментацию.
- `fromCodePoint` запрашивает исходную словарную запись чтений одиночной кодовой точки (варианты с тонами через запятую) и возвращает `null`, если она не покрыта.
- `fromPhrase` запрашивает словарь словосочетаний и возвращает варианты чтения каждой позиции словосочетания; если оно не покрыто, возвращается пустой массив.
- Все методы возвращают результат синхронно; самый первый вызов инициализирует встроенные словари и может занять чуть больше времени.

#### Node.js

В среде Node.js вызывайте тот же provider через публичный facade `autojs6:bridge` и явно объявляйте capability `pinyin`:

```javascript
const { callAutoJs } = require("autojs6:bridge");

(async () => {
  const result = await callAutoJs(
    "pinyin",
    "convert",
    ["中心", { style: "TONE2" }],
    { permissions: ["pinyin"] },
  );
  console.log(result); // [["zhong1"], ["xin1"]]
})();
```

### Частые Вопросы

******

#### Как убедиться, что плагин работает?

Откройте центр плагинов AutoJs6: если плагин `Pinyin` виден и включен, хост его распознал. Затем выполните скрипт из раздела `Самопроверка` выше; вывод `pinyin` подтверждает работу.

#### Скрипт сообщает об отсутствии плагина или недоступности `pinyin`?

Убедитесь, что внутренняя сборка AutoJs6 не ниже 3923, а плагин установлен, авторизован и включен в центре плагинов. Начиная с AutoJs6 v6.8.0 хост больше не содержит встроенной реализации пиньиня, и все преобразование возложено на этот плагин.

#### Почему в списке приложений и на рабочем столе нет значка плагина?

Так и задумано. У плагина нет собственного интерфейса, и он не создает значок запуска; после установки AutoJs6 обнаруживает и вызывает его в фоне, а все взаимодействие происходит внутри AutoJs6.

#### Чтение иероглифа с несколькими вариантами не соответствует ожиданиям?

По умолчанию используется первое чтение каждого одиночного иероглифа. Включите параметр `segment`, чтобы устранять неоднозначность через словарь словосочетаний и сегментацию (например `pinyin.simple(text, false, true)`); когда нужны все варианты, используйте параметр `heteronym`. Если чтение употребительного слова все равно неверно, сообщите через [Issues](https://github.com/SuperMonster003/AutoJs6-Plugin-Pinyin/issues), чтобы словари можно было улучшить.

#### Как выбрать между этим плагином и родственным Pinyin4j?

Выбирайте этот плагин, когда нужны несколько чтений, сегментация, словосочетания или фамильные чтения; выбирайте [Pinyin4j](https://github.com/SuperMonster003/AutoJs6-Plugin-Pinyin4j), когда достаточно легкого поиероглифного преобразования и важен размер APK. Они не конфликтуют и могут стоять вместе; подробнее в разделе `Сравнение Родственных Плагинов` ниже.

#### Обращается ли плагин к сети или запрашивает чувствительные разрешения?

Нет. Все словари встроены в APK, преобразование выполняется на устройстве; манифест объявляет только разрешение плагина для связи с AutoJs6, без сетевых, файловых и других чувствительных системных разрешений.

#### Почему APK занимает около 6 MB?

APK содержит четыре набора данных: словарь одиночных иероглифов, словарь словосочетаний, лексикон сегментации и модель HMM; это цена полной автономности и более высокой точности чтений. Если размер важнее, рассмотрите родственный плагин [Pinyin4j](https://github.com/SuperMonster003/AutoJs6-Plugin-Pinyin4j) размером около 0.3 MB.

#### Почему отклоняется `customDictionary` или вызов Pinyin из Node.js?

Эти маршруты требуют совместимых сборок AutoJs6 и плагина Pinyin. Вызовы Node.js должны объявлять `permissions: ["pinyin"]`. Пользовательский словарь действует только для одного вызова и должен соблюдать документированные пределы числа записей, кандидатов, комбинаций и 64 KiB.

### Разрешения И Безопасность

******

Плагин спроектирован так, чтобы поверхность данных и разрешений была минимальной:

- Минимальные разрешения: манифест объявляет только разрешение плагина AutoJs6 (`org.autojs.permission.PLUGIN`), без сетевых разрешений, разрешений хранилища, камеры и других чувствительных системных разрешений.
- Локальное преобразование: текст передается только через Binder внутри устройства, словари полностью встроены, все происходит офлайн, и данные не покидают устройство.
- Подпись и авторизация: AutoJs6 проверяет подпись плагина, а вызывать его скрипты могут лишь после авторизации и включения в центре плагинов; сервис и точка пробуждения защищены разрешением плагина, поэтому сторонние приложения не могут вызывать их напрямую.
- Открытость и проверяемость: код плагина, упаковка словарей и конвейер генерации документации полностью открыты.

Устанавливайте плагин только со страницы [Releases](https://github.com/SuperMonster003/AutoJs6-Plugin-Pinyin/releases) или из центра плагинов AutoJs6; пакет из неизвестного источника может быть подменен, даже если имя и номер версии совпадают.

### Сравнение Родственных Плагинов

******

AutoJs6 предлагает два официальных плагина пиньиня с разными акцентами, и их можно установить одновременно:

| Аспект | [Pinyin](https://github.com/SuperMonster003/AutoJs6-Plugin-Pinyin) | [Pinyin4j](https://github.com/SuperMonster003/AutoJs6-Plugin-Pinyin4j) |
|---|---|---|
| Реализация | Встроенные словари + сегментация Jieba | Классическая Java библиотека `pinyin4j` |
| Глобальный объект | `pinyin` | `pinyin4j` |
| Несколько чтений | Поддерживается, доступны все варианты | Не поддерживается, только первое чтение |
| Сегментация и словосочетания | Поддерживается (словарь словосочетаний + Jieba) | Не поддерживается, поиероглифное преобразование |
| Режим фамилий | Поддерживается | Не поддерживается |
| Форма вывода | Двумерный массив кандидатов (комбинируется через `compact()`) или компактная строка | Строка с настраиваемым разделителем |
| Стили и форматы | 6 стилей пиньиня | 3 формата тонов + регистр + представление `ü` |
| Размер APK | Около 6 MB (встроенные словари) | Около 0.3 MB |
| Лучше всего для | Точность прежде всего: несколько чтений, словосочетания, имена | Размер и простота прежде всего: быстрое поиероглифное преобразование |

Плагины не зависят друг от друга и не конфликтуют; после установки обоих скрипты могут по необходимости вызывать `pinyin` и `pinyin4j`. Подробнее о плагине Pinyin4j см. [AutoJs6-Plugin-Pinyin4j](https://github.com/SuperMonster003/AutoJs6-Plugin-Pinyin4j).

### Интерфейс Плагина

******

Следующая информация предназначена разработчикам хоста AutoJs6 и плагинов; хост использует эти идентификаторы для обнаружения плагина и согласования возможностей:

```text
application id: io.github.supermonster003.autojs6.plugin.pinyin
plugin id: pinyin
engine: pinyin
variant: default
discovery action: org.autojs.plugin.PINYIN
discovery category: pinyin
wake action: org.autojs.plugin.action.WAKE
binder interface: IPinyinPlugin
binder methods: getInfo / convert / simple / fromCodePoint / fromPhrase
minimum host build: 3923
native library: none (pure JVM, all ABIs)
```

`PinyinPluginService` отвечает на action `org.autojs.plugin.PINYIN` (category `pinyin`) и предоставляет 5 методов через AIDL интерфейс `IPinyinPlugin`; `convert` и `fromPhrase` возвращают двумерные массивы как JSON строки, а параметры передаются в `Bundle` (ключи: `mode` / `style` / `segment` / `heteronym` / `group` / `custom_dictionary_json`). Пользовательские словари требуют capability `pinyin.customDictionary.v1`. Сервис и `WakeActivity` защищены разрешением `org.autojs.permission.PLUGIN`, поэтому сторонние приложения не могут вызывать их напрямую.

### Сборка

******

Этот раздел предназначен разработчикам, желающим собрать плагин из исходников.

Собрать debug APK:

```powershell
.\gradlew.bat :app:assembleDebug
```

Запустить модульные тесты JVM и собрать APK для instrumentation-тестов:

```powershell
.\gradlew.bat :app:testDebugUnitTest :app:assembleDebugAndroidTest
```

Собрать release APK (единый универсальный пакет; после настройки неотслеживаемого `sign.properties` подпись выполняется автоматически):

```powershell
.\gradlew.bat :app:assembleRelease
```

Собрать и проверить подписанный universal APK одной командой, затем создать `SHA256SUMS.txt` и `RELEASE_NOTES.md` на основе английского CHANGELOG:

```powershell
py scripts\release\prepare_release.py
```

Проверить синхронность многоязычных источников документации и сгенерированных файлов (также контролируется CI):

```powershell
py .python\generate_markdown.py --check
```

Параметры сборки собраны в `version.properties`: минимальный SDK 24 (Android 7.0), целевой SDK 37, текущая версия 1.0.3.

### Локализация И Генерация Документации

******

```text
.readme/common.json
.readme/lang_*.json
.readme/template_readme.md
.readme/template_plugin_instruction.md
.changelog/lang_*.json
.changelog/template_changelog.md
.python/generate_markdown.py
app/src/main/assets/doc/CHANGELOG-*.md
app/src/main/res/values-*/strings.xml
app/src/main/res/raw-*/plugin_instruction.md
```

`strings.xml` содержит локализованное описание плагина, а `plugin_instruction.md` содержит инструкции, отображаемые в центре плагинов хоста. README, журнал изменений и инструкции генерируются из JSON источников: отредактируйте источники в `.readme/` и `.changelog/`, затем выполните `py .python/generate_markdown.py`, чтобы пересоздать все артефакты; сгенерированные артефакты никогда не правятся вручную. Команда `py .python/generate_markdown.py --check` проверяет синхронность источников и артефактов.
